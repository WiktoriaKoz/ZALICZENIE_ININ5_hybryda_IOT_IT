# Zasady współpracy (CONTRIBUTING)

Dziękujemy za chęć współpracy przy projekcie!

## Nazewnictwo branchy
- Każda nowa funkcjonalność powinna być tworzona w osobnej gałęzi.
- Nazwa gałęzi: `stolica-imie` (np. `stolica-wiktoria`).

## Zasady commitów
- Komunikaty commitów powinny być krótkie i opisowe.
- Przykład: `Dodano sekcję Paryż w index.html`.

## Pull Request
- Każdy PR musi zawierać opis zmian.
- PR powinien być skierowany do gałęzi `main`.

## Komunikacja
- Wszelkie pytania i uwagi zgłaszamy przez GitHub Issues lub Trello.
